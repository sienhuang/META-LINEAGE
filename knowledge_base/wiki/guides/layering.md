# 数仓分层规范

> 给 Agent 和数仓工程师的分层约定。理解分层 = 知道「该从哪一层取数」。

## 分层模型

| 层   | 全称 | 定位 | 数据库命名规则/表格命名规则           | 该不该直接查               |
|-----|------|------|--------------------------|----------------------|
| ODS | Operational Data Store | 贴源层，与业务库结构一致，不做清洗 | `{项目}_ods`/{服务器区域}_{描述}* | ❌ 尽可能数仓使用，除非没有可用上层模型 |
| DWD | Data Warehouse Detail | 明细层，清洗后的事实明细，最细粒度 | `_dwd`/{业务域}_{描述*}_{周期}  | ✅ 灵活分析首选             |
| DWM | Data Warehouse Summary | 汇总层，按主题/维度轻度聚合 | `_dwm`/{业务域}_{描述*}_{周期}  | ✅ 性能更好               |
| ADS | Application Data Store | 应用层，面向报表/看板的结果表 | `_ads`/{业务域}_{描述*}_{周期}  | ✅ 大盘指标直接取            |
| DIM | Dimension | 维度层，描述性维表(用户/商品/地区) | `_dim`/{业务域}_{描述*}_{周期}                  | ✅ 用户维度JOIN 用         |

## 取数优先级（给 Text-to-SQL Agent 的决策规则）

1. **大盘固定指标** → 优先 `ads`（已算好，最快最准）
2. **按维度下钻 / 标准聚合** → 用 `dwm`
3. **灵活明细 / ads/dwm 没有的口径** → 回到 `dwd` 自行聚合 -> 非必要不直接查ods
4. **需要维度属性且ads/dwm没有对应维度信息** → JOIN `dim`

## 命名规范

```
{业务域}_{描述*}_{周期}
dwm_login_active_di   # dwm层 / 登陆 / 活跃 / 日增量
mt_dim.dim_active_role_zone_did_df   # dim层 / 活跃/role_zone_did粒度/日全量
```

周期后缀：`di` 日增量 · `df` 日全量 · `mi` 月增量 · `mf` 月全量
